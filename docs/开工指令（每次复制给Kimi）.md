# 开工指令

> 用法：每次在 ZCode 里新开对话，把下面「第一次开工」或「继续开工」整段复制给 Kimi。

---

## 第一次开工

```
你是「畅撩交友」项目唯一的开发者，要从 0 独立完成安卓 App（Kotlin + Compose）、后端和管理后台（MineAdmin 3.2）。

开始前请严格按顺序做：
1. 完整阅读 开发规则/00-必读-总规则.md，读完用 5 句话复述你理解的铁律。
2. 阅读 开发规则/08-开发任务清单.md 的 P0 部分。
3. 从 T0.1 开始执行。T0.1 会把「开发规则」复制到 changliao/docs/，之后所有文档都以 changliao/docs/ 为准，进度写在 changliao/PROGRESS.md。

规则提醒：
- 一次只做一个任务，做完自检、更新 PROGRESS.md、git commit，再做下一个。
- 写 UI 前必读 docs/03-UI设计规范.md；页面里只能用公共组件，不准写死颜色、字号、dp。
- 碰到金币、积分、扣费、提现，必读 docs/06-计费与资金规则.md，不准自己发明规则。
- 文档没写清楚的地方，记到 PROGRESS.md 的「待确认问题」，不要自己改需求文档。
- 自检命令没跑通，不准说任务完成。
```

## 继续开工

```
继续开发「畅撩交友」项目。

请按顺序做：
1. 阅读 docs/00-必读-总规则.md。
2. 阅读 PROGRESS.md，告诉我：当前任务是什么、上次停在哪、下一步要做什么。
3. 阅读 docs/08-开发任务清单.md 里当前任务，以及该任务「读」列出的文档章节。
4. 继续执行当前任务，完成后按 docs/09-测试与自检清单.md 自检，把记录写进 PROGRESS.md，git commit，然后进入下一个任务。

注意：不要凭记忆写代码，一切以 docs/ 和 PROGRESS.md 为准。
```

## 检查 Kimi 有没有偷懒（你可以随时发）

```
暂停开发。请做一次自查并如实回答：
1. 运行 bash scripts/check-all.sh，贴出最后 30 行输出。
2. 列出 PROGRESS.md 里标记完成、但没有自检记录的任务。
3. 列出 feature/ 目录里没有使用 ClScaffold 的页面。
4. 列出 06-计费与资金规则.md 第 10 节里还没有测试的场景编号。
5. 列出 01-产品需求与页面清单.md 里已经开发、但缺少加载/空/错误状态的页面。
发现问题先记到 PROGRESS.md，再逐个修复。
```
