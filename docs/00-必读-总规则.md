# 00 必读：总规则（每次开工第一个读）

> 你是这个项目唯一的开发者。你要从 0 开始，独立完成三端：**安卓 App + 后端 + 管理后台**。
> 你的记忆不可靠，所以**一切以文档和 `PROGRESS.md` 为准**，不能凭印象写代码。

---

## 1. 项目一句话

「畅撩交友」是一个**一对一付费私信聊天** App（对标「伊对」）：男用户充值金币、给女用户发私信按条扣金币；女用户收到消息按等级分成拿积分，积分可申请提现。没有在线支付，充值和打款都由后台人工完成。

## 2. 技术栈（不允许更换）

| 端 | 技术 |
|---|---|
| 后端 | MineAdmin 3.2（Hyperf 3.2 + PHP 8.2+ + Swoole 5+ + MySQL 8 + Redis） |
| 管理后台前端 | MineAdmin-Vue 3.2（Vue 3 + TypeScript + Element Plus + MineAdmin 组件） |
| 安卓 | Kotlin + Jetpack Compose + Material3，单 Activity，最低 API 26 |
| 实时消息 | Hyperf WebSocket（只负责推送，发消息走 HTTP） |
| 图片存储 | 服务器本地磁盘（通过存储接口封装，以后可换 OSS） |

不接：微信支付、支付宝、短信验证码、腾讯 IM、音视频 SDK、厂商推送。

## 4. 铁律（违反任何一条，任务都算失败）

1. **一次只做一个任务。** 按 `08-开发任务清单.md` 的顺序做，不跳步、不并行、不顺手做别的。
2. **先读后写。** 开始任务前，读完该任务「需要读」列出的文档章节，再动手。
3. **不准自创需求。** 文档没写的功能不做；文档写了的功能一个都不能少。遇到文档没说清的地方，按「第 7 节 遇到不确定时」处理。
4. **UI 必须统一。** App 只能用 `core/designsystem` 里的颜色、字号、间距和公共组件；后台只能用 MineAdmin 组件和 `07` 文档里的页面模板。**禁止在页面代码里写死颜色、字号、dp 数值。** 详见 `03-UI设计规范.md`。
5. **先建公共模块，再写页面。** 公共组件缺了就先补到公共模块里，不准在页面里临时造一个长得差不多的。
6. **钱只在服务端算。** App 只展示服务端返回的价格和余额，不准在 App 里计算扣费或分成。
7. **所有可调数字都从配置读。** 价格、比例、免费条数、汇率、提现档位……全部来自后台配置表，代码里不准写死业务数字（默认值只能写在数据库初始化种子里）。
8. **金额用整数。** 金币、积分都是整数；比例用「万分比」整数（3000 = 30%）。禁止用 float/double 存或算钱。
9. **每笔资金变动都要有流水。** 余额变动和写流水必须在同一个数据库事务里。
10. **自测通过才算完成。** 每个任务必须跑通 `09` 文档里对应的检查命令，并把结果写进 `PROGRESS.md`。没跑、跑不过、只跑了一半，都不算完成。
11. **不准删除或跳过测试**来让检查通过；不准用 `@Ignore`、`markTestSkipped`、注释掉断言等方式绕过。
12. **语音/视频只做页面，不做功能。** 受后台开关控制，默认关闭。详见 `01` 文档第 4 节。
13. **合规要求不能删：** 充值页和用户协议必须显示「本平台为付费聊天服务，部分女用户为平台签约陪聊人员」；女号资料必须是本人真实信息（后台批量开号页要有这条提示）。
14. **每个任务完成后 git commit 一次**，提交信息格式：`[任务编号] 简短说明`，例如 `[T3.2] 发现页列表接口`。
15. **不准修改 `开发规则/` 里的需求文档。** 发现文档有矛盾，记到 `PROGRESS.md` 的「待确认问题」里，不要自己改文档。

## 5. 每次开工的固定流程

```
1. 读 00-必读-总规则.md（本文件）
2. 读 PROGRESS.md，看「当前任务」和「上次停在哪」
3. 读 08-开发任务清单.md，找到当前任务
4. 读当前任务列出的「需要读」章节
5. 在 PROGRESS.md 把当前任务标记为「进行中」
6. 写代码
7. 按 09-测试与自检清单.md 做自检，全部通过
8. 在 PROGRESS.md 记录：完成内容、改了哪些文件、自检命令和结果
9. git commit
10. 进入下一个任务（回到第 3 步）
```

如果一次会话做不完一个任务：在 `PROGRESS.md` 的「上次停在哪」写清楚做到哪一步、下一步要做什么、还有哪些文件没改完。

## 6. 完成的标准（Definition of Done）

一个任务只有同时满足下面全部条件，才能在 `PROGRESS.md` 里打勾：

- [ ] 任务「验收标准」的每一条都做到了
- [ ] 后端：`composer test` 全部通过，新功能有对应测试
- [ ] 后端：`composer analyse`（PHPStan）无新增错误
- [ ] 安卓：`./gradlew testDebugUnitTest assembleDebug` 通过
- [ ] 安卓：`scripts/check-ui.sh` 通过（没有写死的颜色、字号、dp）
- [ ] 后台：`pnpm build` 通过，`pnpm lint` 无错误
- [ ] 涉及的页面四种状态都做了：加载中、空数据、出错可重试、正常
- [ ] 对照设计图检查过页面（说明对照了哪张图）
- [ ] `PROGRESS.md` 已更新，git 已提交

只改后端的任务可以不跑安卓检查，反之亦然；但 `scripts/check-all.sh` 在每个**阶段**结束时必须整体跑一次。

## 7. 遇到不确定时

按这个顺序找答案：

1. `需求确认记录.md`（甲方原话，优先级最高）
2. `06-计费与资金规则.md`、`01-产品需求与页面清单.md`
3. 设计图和 HTML 原型
4. 都找不到：选**最简单、不涉及钱、可以后台配置**的做法，并在 `PROGRESS.md` 的「待确认问题」里写下：问题是什么、你选了什么、为什么。

**涉及钱的规则不准自己猜。** 如果 06 文档没写到，就把该功能先停下，记到「待确认问题」，跳到下一个不相关的任务。

## 8. 禁止事项

- 禁止引入文档没列出的大型框架（例如换成 XML 布局、换 Flutter、换 Laravel、换 Ant Design）。小型工具库需要时可以加，但要在 `PROGRESS.md` 记录名称、版本和用途。
- 依赖版本必须写死（Gradle 用 `libs.versions.toml`，PHP 用 `composer.lock`，前端用 `pnpm-lock.yaml`），禁止 `+`、`latest`、`*`。
- 禁止把密钥、密码、JWT secret 提交到 git。用 `.env`，并提交 `.env.example`。
- 禁止在日志里打印密码、身份证号、完整 token。
- 禁止 App 端拼 SQL 或信任 App 传上来的价格、余额、性别、等级。
- 禁止一个文件超过 500 行。超过就拆。
- 禁止复制粘贴出两份相同逻辑。第二次用到就提取成公共函数或组件。
