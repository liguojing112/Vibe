# 05 接口规范

> App 接口前缀 `/api/v1`，后台接口前缀 `/admin/cl`。
> 新增接口必须先在本文档对应表格里找到它；表里没有的接口不要做，有需要记到 `PROGRESS.md`。
> 每个接口都要写 Swagger 注解（模仿 MineAdmin 自带 Controller）。

---

## 1. 统一响应格式

```json
{ "code": 200, "message": "成功", "data": { } }
```

- 成功：`code = 200`。
- 业务错误：HTTP 状态码仍为 200，`code` 为第 3 节的业务码，`message` 是**可以直接给用户看**的中文。
- 未登录 / token 失效：HTTP 401，`code = 401`。
- 参数校验失败：`code = 422`，`message` 为第一条错误。
- App 接口用自定义的 `App\Http\Api\ApiResult`（输出格式与 MineAdmin 的 `Result` 完全一致，但 `code` 允许是业务码整数）。后台接口继续用 MineAdmin 的 `Result`。

### 分页

请求：`page`（从 1 开始）、`page_size`（默认 20，最大 50）。
响应：

```json
{ "list": [], "total": 120, "page": 1, "page_size": 20, "has_more": true }
```

聊天消息用游标分页：请求 `before_id`（取比它更早的），响应 `list` + `has_more`。

### 字段命名

- JSON 字段一律 `snake_case`。
- 时间一律字符串 `yyyy-MM-dd HH:mm:ss`（北京时间）。
- 金币、积分是整数；人民币返回两个字段：`xxx_fen`（整数分）和 `xxx_text`（例如 `"12.50"`），App 只显示 `_text`。
- 布尔用 `true/false`。

## 2. 鉴权

- App：登录返回 `access_token`（JWT，有效期 7 天）和 `refresh_token`（30 天）。请求头 `Authorization: Bearer {access_token}`。
- `AppAuthMiddleware` 每次请求检查：token 有效、用户存在、`status = 1`。被封号返回业务码 10004，App 收到后弹出封禁原因并退出登录。
- 用户 ID **只能从 token 取**，不准信任请求参数里的 user_id。
- 限流（Redis）：登录 每 IP 每分钟 10 次；发消息 每用户每秒 3 条；上传 每用户每分钟 20 次；超限返回 10005。

## 3. 业务错误码（`App\Model\Enums\Cl\BizCode`）

| 码 | 含义 | App 处理 |
|---|---|---|
| 10001 | 账号或密码错误 | 提示 |
| 10002 | 账号已存在 | 提示 |
| 10003 | 密码错误次数过多，已锁定 X 分钟 | 提示 |
| 10004 | 账号已被封禁（data 带 reason、until） | 弹窗后退出登录 |
| 10005 | 操作太频繁 | 提示 |
| 10006 | 旧密码错误 | 提示 |
| 20001 | 金币余额不足（data 带 balance、needed） | 弹出 P30 |
| 20002 | 积分不足 | 提示 |
| 20003 | 提现条件不满足（未实名/档位不对/次数用完，message 说明原因） | 提示 |
| 30001 | 对方不存在或已注销 | 提示 |
| 30002 | 对方已设置不接收你的消息（被拉黑） | 提示 |
| 30003 | 不能给同性发送 | 提示 |
| 30004 | 消息内容不合法（为空/过长/图片不合法） | 提示 |
| 40001 | 状态不允许此操作 | 提示 |
| 40002 | 资料审核中，请勿重复提交 | 提示 |
| 40003 | 实名信息格式错误 | 提示 |
| 40004 | 需要开通会员 | 跳 P12 |
| 50001 | 功能暂未开放 | 提示 |

### 4.5 聊天

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/chat/conversations` | 会话列表（分页）：对方简要资料、最后消息摘要、时间、未读数（App 端会本地持久化，本接口用于首次拉取 + 静默刷新） |
| DELETE | `/chat/conversations/{id}` | 删除会话（只对自己隐藏） |
| GET | `/chat/conversations/with/{userId}` | 进入聊天页时调用：会话 ID（没有则返回 null，第一次发消息时创建）+ **收费信息** `fee`（见下） |
| GET | `/chat/messages` | `conversation_id`、`before_id`、`limit=30`（历史消息以安卓本地库为主，本接口用于本地缺失时的补拉） |
| POST | `/chat/send` | `receiver_id`、`type`（1 文字 2 图片）、`content`、`client_msg_id`（App 生成 UUID）。返回 `message`、`fee`（发送后的最新收费信息）、`balance` |
| POST | `/chat/read` | `conversation_id`，标记已读 |
| GET | `/chat/unread` | 未读总数（会话 + 访客 + 系统通知，分别返回） |
| GET | `/chat/sync` | `after_id`：拉取我收到的、id 大于它的消息（重连/回前台**增量补拉**，写入安卓本地库的同步游标） |
| GET | `/chat/fee-rules` | 收费说明弹窗文本（按当前配置生成的条目数组） |

`fee` 结构（只对男用户有值，女用户返回 `null`）：

```json
{
  "next_price": 5,            // 下一条要扣的金币，0 表示免费
  "free_reason": "PAIR_FREE", // 下一条免费原因，收费时为 null
  "pair_free_left": 2,        // 对子免费还剩几条
  "vip_free_left": 0,         // 今天会员免费还剩几条
  "balance": 360,
  "strip_text": "还可免费发送 2 条 · 之后 5 币/条 · 余额 360 币"   // 收费条文案，服务端拼好
}
```

> **聊天本地化（客户 2026-10-11 确认）**：App 端以本地库（Room）为**聊天记录主数据源**。`/chat/send` 返回的正式消息、WebSocket 推送的消息、`/chat/sync` 补拉的消息，都要写入本地库；上述聊天接口的数据用于**首次拉取 + 静默刷新**，服务端不作为展示数据源。扣费与余额仍只在服务端计算（铁律 6），本地只存展示用内容。

## 5. WebSocket

- 地址：`ws://{host}:9502/ws?token={access_token}`。token 无效直接断开。
- 服务端 → App 的消息格式：

```json
{ "event": "message.new", "data": { ...与 /chat/messages 里的单条消息结构相同 } }
```

| event | 何时推送 | data |
|---|---|---|
| `message.new` | 有人给我发消息/礼物 | 消息对象 + `conversation_id` |
| `unread.update` | 未读数变化 | 同 `/chat/unread` |
| `notice.new` | 新系统通知 | 通知对象 |
| `account.banned` | 被封号 | reason、until |
| `pong` | 回应心跳 | `{}` |

- App → 服务端：只发心跳 `{"event":"ping"}`，每 30 秒一次。**发消息不走 WebSocket**，一律走 `POST /chat/send`。
- 用户在线 = 有 WebSocket 连接；断开后 `last_active_at` 更新。在线状态存 Redis `online:{userId}`。

## 6. 后台接口

后台接口按 07 文档的菜单逐个实现，路径规则：`/admin/cl/{模块}/{动作}`，例如：

| 方法 | 路径 |
|---|---|
| GET | `/admin/cl/user/list`（`gender` 区分男女） |
| PUT | `/admin/cl/user/{id}` |
| POST | `/admin/cl/user/batch-create` |
| GET | `/admin/cl/user/batch/{batchNo}/export`（只能导出一次） |
| POST | `/admin/cl/user/{id}/ban`、`/unban`、`/level`、`/reset-password` |
| POST | `/admin/cl/finance/recharge` |
| POST | `/admin/cl/finance/coin-deduct`、`/point-adjust` |
| POST | `/admin/cl/withdraw/{id}/approve`、`/reject`、`/paid` |
| GET/PUT | `/admin/cl/config/{group}` |

每个后台接口都要加 MineAdmin 的权限注解（`#[Permission(code: 'cl:user:list')]` 形式），权限码清单见 07 文档第 4 节。
