## 1. 测试要求

### 1.1 后端（PHPUnit，`server/tests/`）

- 用 MineAdmin 自带的测试基础类（`tests/HttpTestCase.php`）写接口测试。
- 测试用**单独的数据库** `cl_test`（在测试环境配置里指定，绝不能连开发库或正式库），每个测试前清理业务表或用事务回滚。
- 每个 App 接口至少有：1 个成功用例 + 1 个未登录用例 + 主要失败用例（参数错误、权限不足、业务错误码）。
- 每个后台接口至少有：1 个成功用例 + 1 个无权限（403）用例。
- `06-计费与资金规则.md` 第 10 节的 34 个场景**全部**要有测试，测试方法名里写场景编号，例如 `testScene06BalanceNotEnough()`。
- Service 里的纯计算（`MessagePricingService`、积分公式）写单元测试，覆盖边界值（0、1、刚好等于、差 1）。
- 并发测试（场景 8）：用 Hyperf 协程 `parallel()` 同时发起请求。

### 1.2 后台前端（admin-web）

- `pnpm lint`（vue-tsc 类型检查 + eslint + stylelint）无错误。
- `pnpm build` 成功。
- 手动检查：每个页面打开不报错、搜索、分页、新增/编辑弹窗、危险操作二次确认都能用。在 `PROGRESS.md` 写下检查了哪些页面。

### 1.3 安卓

- 每个 ViewModel 写单元测试（MockK 模拟 Repository，Turbine 测 StateFlow）：至少覆盖 加载成功、空数据、出错、主要用户操作。
- `core/common` 里的工具（时间格式化、金额格式化、身份证校验、手机号校验、密码规则）全部写单元测试。
- 网络层：用 MockWebServer 测 `ApiResult` 解析（成功、业务错误码、401、网络错误）。
- 聊天页 ViewModel 必须测：发送成功刷新收费条、20001 时弹余额不足且输入内容保留、发送失败可重发、client_msg_id 重发时不变。

### 2.2 `scripts/check-money.sh`（防止绕过钱包服务改余额）

```bash
#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")/../server/app"
# 只有这些文件可以直接写钱包表
ALLOW='Service/Cl/Wallet/CoinWalletService.php|Service/Cl/Wallet/PointWalletService.php|Repository/Cl/CoinWalletRepository.php|Repository/Cl/PointWalletRepository.php|Model/Cl/CoinWallet.php|Model/Cl/PointWallet.php'
HITS=$(grep -rnE "cl_(coin|point)_wallet|CoinWallet::|PointWallet::|CoinWalletRepository|PointWalletRepository" . | grep -vE "$ALLOW" || true)
if [ -n "$HITS" ]; then
  echo "❌ 以下位置绕过了钱包服务："; echo "$HITS"; exit 1
fi
# 禁止用浮点算钱
FLOAT=$(grep -rnE "\(float\)|floatval\(|round\(" Service/Cl/Billing Service/Cl/Wallet Service/Cl/Withdraw || true)
if [ -n "$FLOAT" ]; then
  echo "❌ 资金代码里出现浮点运算："; echo "$FLOAT"; exit 1
fi
echo "✅ money 检查通过"
```

### 2.4 `scripts/check-ui.sh`（安卓 UI 统一性）

```bash
#!/usr/bin/env bash
set -euo pipefail
shopt -s nullglob
ROOT="$(dirname "$0")/../android/app/src/main/java/com/qichuang/changliao"
FEATURE="$ROOT/feature"
DS="$ROOT/core/designsystem"
FAIL=0

# 1. feature 里禁止出现的写法
PATTERN='Color\(|\.dp([^a-zA-Z]|$)|\.sp([^a-zA-Z]|$)|FontWeight\.|RoundedCornerShape\(|MaterialTheme\.|material3\.Button([^a-zA-Z]|$)|(^|[^A-Za-z])TextField\(|OutlinedTextField\(|AlertDialog\(|ModalBottomSheet\(|Snackbar\('
HITS=$(grep -rnE "$PATTERN" "$FEATURE" || true)
if [ -n "$HITS" ]; then echo "❌ feature 中出现硬编码样式或原生组件："; echo "$HITS"; FAIL=1; fi

# 2. 每个公共组件都必须出现在组件预览页
GALLERY=$(find "$ROOT" -name 'DesignSystemGalleryScreen.kt' | head -1)
if [ -z "$GALLERY" ]; then echo "❌ 缺少 DesignSystemGalleryScreen.kt"; FAIL=1; else
  for f in "$DS"/component/*.kt; do
    name=$(basename "$f" .kt)
    grep -q "$name" "$GALLERY" || { echo "❌ 组件 $name 没有加到组件预览页"; FAIL=1; }
  done
fi

# 3. 页面里禁止直接写中文价格单位拼接（价格文案必须来自服务端或 MoneyFormat）
HITS2=$(grep -rnE '"[^"]*币/条' "$FEATURE" || true)
if [ -n "$HITS2" ]; then echo "❌ feature 中手写了价格文案，请用 MoneyFormat："; echo "$HITS2"; FAIL=1; fi

[ $FAIL -eq 0 ] && echo "✅ UI 检查通过" || exit 1
```

> 说明：第 1 条里 `(^|[^A-Za-z])TextField\(` 是为了允许 `ClTextField(`。如果误报，修改 `ClXxx` 组件命名，**不准**修改脚本放宽规则。

## 6. 最终验收清单（P9 阶段使用）

**流程走查（用真实的后台和 App 走一遍，每步写结果）：**

1. 后台批量开 3 个女号 → 导出 CSV → 用其中一个登录 App → 上传头像和资料 → 后台审核通过 → 男号在发现页能看到她。
2. 男号自己注册 → 后台客服给他充值 100 金币 → App 余额显示 100。
3. 男号给女号发 3 条免费消息 → 第 4 条扣 5 金币 → 女号实时收到 → 女号积分 +15（未实名则 +7）。
4. 男号余额不足时发送 → 弹出余额不足 → 去充值页 → 返回后输入内容还在。
5. 双方互关 → 男号发消息不扣费。
6. 男号送礼物 → 金币减少 → 女号积分增加 → 聊天里出现礼物消息。
7. 男号买会员 → 能看完整访客 → 每天多 10 条免费。
8. 女号完成签到任务 → 积分增加，但等级进度不变。
9. 女号累计收益达到 Lv2 门槛 → 自动升级 → 收到通知 → 单价变成 Lv2。
10. 女号提交实名 → 后台通过 → 申请提现 50 元 → 积分冻结 → 财务通过 → 标记已打款 → 冻结清零 → 收到通知。
11. 另一次提现被驳回 → 积分退回。
12. 男号发送带敏感词的消息 → 正常送达 → 后台待审消息出现 → 审核员标记违规并封号 → 男号 App 被踢下线并看到封禁原因。
13. 女号举报男号 → 后台举报处理 → 判定违规。
14. 后台打开语音/视频开关 → App 出现入口 → 点拨打提示「功能暂未开放」，余额不变 → 关闭开关后入口消失。
15. 客服账号登录后台：看不到提现审核、运营配置；财务账号看不到充值；审核员看不到资金。
16. 修改后台计费配置（免费条数改 0、Lv1 单价改 8）→ App 收费条立即按新规则显示。
17. 后台「平台收入」当天数据 = 以上操作的金币合计和积分合计。
