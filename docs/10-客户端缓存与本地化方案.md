## 1. 聊天消息本地化

### 1.1 职责划分（客户确认）

| 端 | 职责 |
|---|---|
| 安卓本地库 | **聊天记录的主数据源**。消息、会话、未读数都从本地读，界面秒开 |
| 服务端 | 转发消息、计费扣款、敏感词审核与监管；**不作为聊天记录的展示数据源** |

> ⚠️ 待确认：服务端为监管和举报取证需要保留消息多久？保留策略会影响历史消息补拉接口的设计。

### 1.2 本地库选型

`02` 文档 4.2 的依赖列表里**没有本地数据库**，本方案需要新增 **Room**。
（引入后请同步更新 `02` 文档 4.2 的依赖清单和 `PROGRESS.md` 的「新增依赖记录」表。）

建议的表：

| 表 | 内容 |
|---|---|
| `message` | 消息本地全量：`server_id`、`client_msg_id`、会话 id、收发方向、类型（文本/图片/礼物）、内容、媒体本地路径、`status`、`created_at` |
| `conversation` | 会话：对方 id、最后一条消息摘要、未读数、最后时间 |
| `sync_state` | 同步游标（每个会话最后同步到的消息 id） |

### 1.3 消息状态机

```
sending → sent（服务端确认）
        → failed（可点击重发）
```

- 发送中：`status = sending`，界面立刻出气泡（见第 2 节）。
- 发送成功：写入服务端返回的正式消息。
- 发送失败：`failed`，气泡显示红色感叹号，点击重发（P06 已有此要求）。
- **App 被杀时仍在 `sending` 的**：下次启动超过 60 秒的改为 `failed`，避免卡在发送中。

### 1.4 同步策略（本项目是 WebSocket，不是轮询）

服务端用 Hyperf WebSocket 推送（`02` 文档 4.4），所以**不采用轮询 inbox 的模式**：

- App 在前台：WebSocket 保持连接，收到推送即写本地库并更新 UI。
- 回到前台 / 断线重连成功：调用一次「拉取未读」接口补齐（沿用 `02` 文档 4.4 已有约定）。
- 同一时间只跑一轮同步，用协程 `Mutex` 或 `running` 标记防重入。
- **网络错误吞掉等下一轮**，不弹错误提示；只有登录失效（401）向外抛，由 `AuthInterceptor` 退出登录。

## 2. 发送流程：先出气泡（乐观 UI）

这是原文中最有价值的一条，与 P06「发送中/失败（红色感叹号，点击重发）」和 `client_msg_id` 幂等要求完全对应。

1. 写一条本地记录，`status = sending`，**界面立刻出气泡**，不等网络。
2. 发成功：替换成服务端返回的正式消息（图片直接用上传时的那份本地文件，不再下载）。
3. 发失败：改为 `failed`，气泡显示感叹号，点击重发。
4. 重发时 `client_msg_id` **保持不变**（服务端靠它做幂等，避免重复扣费）。
5. 没发出去的图片也要先存本地，重发时直接用。

> 注意：扣费和余额仍以服务端返回为准（铁律第 6 条）。本地只负责显示，不计算价格。
> 服务端返回 20001 余额不足时，按 P06 要求弹 P30，并**保留输入框内容**。

## 3. 静默刷新与持久化（客户确认）

策略：**stale-while-revalidate —— 先显示本地的，再静默刷新。**

- 打开页面时先把本地持久化的数据渲染出来，页面**立刻有内容**，不转圈。
- 同时发起网络请求，拿到后静默替换。
- 适用于：聊天列表、会话消息、发现页列表、「广场」、个人主页、系统消息、收益明细等所有列表。

规则：

1. **缓存不设 TTL**，只用于马上有内容显示，最终以接口为准。
2. **解码失败当作没缓存**。数据类的新增字段必须是可空的或有默认值，否则旧缓存整体读不出来。
3. **缓存键带版本号**（如 `v2.list.discover.<userId>`），改结构时换版本，旧的自动作废。
4. **只写当前登录用户的**。切换账号时先清空内存，避免把 A 的数据写到 B 名下。
5. **退出登录时清空所有内存缓存**，本地库按产品需要保留或清除（退出登录保留、注销删除）。
6. 节流：同一列表 60 秒内切回来不重复请求；**下拉刷新不受限制**，始终立即请求。

## 4. 图片缓存

本项目用 **Coil**（`02` 文档 4.2 已定），Coil 自带内存缓存 + 磁盘缓存，
**不自建一套**。需要做的是正确配置和使用：

- 列表里的图片显式指定显示尺寸（Coil 的 `size()`），避免原图解码占内存。
- 头像等固定小图指定固定尺寸。
- **上传成功后预热**：换头像、传相册成功后，把本地文件直接写入 Coil 磁盘缓存，自己不用再下载一次。
- 同一张图并发只下载一次（Coil 已处理）。
- 图片加载失败（403/404/410）短期内不重试，避免反复请求。
- **跨主机跳转时去掉 `Authorization` 头**（媒体地址跳到 CDN 时，用 OkHttp Interceptor 处理），
  不要把 token 发给第三方域名。
- 聊天图片走本地库管理的文件路径，生命周期跟随聊天记录。

## 5. 列表 / 页面缓存

实现很薄：一个 `LocalCache` 封装，`load<T>(key)` / `save<T>(value, key)` / `remove(key)`，JSON 原子写入。

本项目建议缓存的键：

| 键 | 内容 | 限制 |
|---|---|---|
| `list.conversations.<userId>` | 会话列表 | 全量 |
| `list.discover.<tab>.<userId>` | 发现页各 Tab 第一页 | 前 20 条（与接口分页大小一致） |
| `list.square.<userId>` | 「广场」第一页 | 待「广场」需求明确后定 |
| `list.visitors.<userId>` | 最近访客 | 第一页 |
| `list.notices.<userId>` | 系统消息 | 第一页 |
| `profile.<viewerId>.<targetId>` | 个人主页 | 接口返回「不存在」时删除 |
| `wallet.summary.<userId>` | 钱包/收益概览 | — |
| `blacklist.<userId>` | 黑名单 | — |

## 6. 网络层

| 用途 | 配置 |
|---|---|
| 业务接口 | 共享的 OkHttp + Retrofit，超时 30 秒，`AuthInterceptor` 加 token |
| 图片 | Coil 自带的 loader，无需单独配置 |
| WebSocket | `ChatSocket`（`02` 文档 4.3）：30 秒心跳，断线按 1s/2s/4s…最大 30s 重连 |

所有请求统一经过 `AuthInterceptor`：跨主机跳转去掉 `Authorization`；收到 401 清登录态回登录页；
收到 10004（封号）弹窗并退出登录（`02` 文档 4.2 已有约定）。

## 7. 本地小状态（DataStore）

`02` 文档 4.3 已定：DataStore 存 token、筛选条件、提醒开关。补充建议：

- 键里带用户 id，避免切换账号串数据。
- 只放非敏感的小开关，**token 是否加密存储需确认**（DataStore 默认不加密，
  如需加密要用 `EncryptedSharedPreferences` 或 Android Keystore）。
- 筛选条件（P07）、消息提醒开关（P15）按现有设计存这里。

## 8. 设计注意事项（通用经验，务必遵守）

1. **本地生成的 id 必须和服务端 id 同格式**（例如都是 32 位十六进制随机串），
   否则会被存储层的格式校验静默挡掉，且**不报错**。存完要读回来确认。
2. **本地数据要有容量管理**：设置页显示占用空间，支持按会话清理，媒体文件单独设上限。
3. **从第一天就做数据库版本迁移**（Room 的 `version` + `Migration`），不要等上线后才补。
4. **「清理缓存」的文案要和实际行为一致**，明确说明不会删聊天记录。
5. **聊天页滚动与本地加载配合**：本地读出消息后立刻贴底；图片解码变高、键盘弹出、面板打开时，
   如果原本停在底部，要重新贴底。
6. **退出登录时清空所有内存缓存**。
7. **图片地址应不可变**（新上传生成新地址）。若做不到，改用 `If-None-Match` 条件请求或在地址里带版本。
